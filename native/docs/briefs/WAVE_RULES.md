# Wave agent rules (real products per trade). Read with CLAUDE.md, DEALERSHIP_AND_PRODUCTS_BRIEF.md (binding) and native/docs/audit/products_by_trade.md (your wave's rows and the 'Models and tabs' section).

Goal: every trade of your wave sells real things: items with cost, stock/inputs, lead time, capacity, price vs fair value, live profit/loss slider, real supplier or recipe, as the audit proposes for the model. Foundation (already on origin/native-swiftui): `Businesses/ItemModels.swift` (item record v2, key `itemsv2`, live profit/loss, sale probability, supply, migration `ItemModels.migrate`), `ItemPageActions.swift`, app `ItemPageView.swift` (items list like the staff list, item page blocks). Your trades are switched on by putting them in YOUR registry file `Businesses/ItemWave<N>.swift` (already exists, empty set).

## File ownership (parallel agents, no double work)
- Create/edit ONLY: your own new files `Businesses/Wave<N>*.swift`, `Businesses/Resources/wave<N>_*.json`, `Features/Company/Wave<N>*.swift`, `Tests/LedgerTests/Wave<N>Tests.swift`, your `ItemWave<N>.swift`, and `native/docs/waves/wave<N>.md` (your notes: decisions, save keys, test rows).
- Shared files (`trades.json`, `itemcatalog.json`, `tables.json`, `ItemModels.swift`, `ItemPageView.swift`, `CompanySales.swift`, `DECISIONS.md`, `SAVE_FORMAT.md`, `HANDS_ON_TEST_PLAN.md`, `RELEASE_NOTES.md`): do NOT edit, except line-local changes inside the entries of YOUR trades in `trades.json`/`itemcatalog.json`/`tables.json`. If the shared item page needs a new block for your model, create `Features/Company/Wave<N>ItemBlocks.swift` and tell the lead the one-line hook to add; do not edit `ItemPageView.swift`.
- Never touch: UsedCarDealer.swift, Marketplace*.swift, CarDealer*.swift, DealerAddons.swift, Brokers*.swift (other agents).

## Quality
- COMMIT LOCALLY, NEVER PUSH. The app compiles only on macOS CI: grep every call vs definitions, imports (Countries for Currency), exhaustive switches, ViewBuilder <= 10, no SwiftUI/Foundation name clashes, no digit \u{} escapes, PressableStyle not .plain, popups via GamePopup, wrap engine types for sheets.
- SIMULATION_RULES.md: no artificial caps/floors, balance causes not outcomes; real money through Ledger/Payments, `Ledger.gaps` empty; old saves unchanged (new keys only when set, migration only for opted-in trades).
- For EACH trade in your wave: real item set per real life (not titles), per-item economics, supplier/recipe/lead time, capacity, sensible add-item catalog, staff roles and pay plans where the job sells (commission etc.), tools from `EQ_KINDS` correct for the real trade, a 2-year survival probe of a competent owner per trade (report profit, no clamps; compare before/after wave: a trade must not become unprofitable by design, if so find the cause), and a test.
- Run only filtered suites (`swift test --filter Wave<N>` and the consistency tests: ItemModelsTests, CountryNeutralityTests, MoneyLiteralLintTests, SaveRoundTripTests). Swift: /opt/swift/swift-6.0.3-RELEASE-ubuntu24.04/usr/bin. Report: sha, one line per trade (what it sells now, model), questions with options only.
